# Private story localization

These catalogs are server-only. Browser code may import `shared/locale.ts` and public character profiles, but must never import these files or `server/localization.ts`.

`en.json` is the canonical English template array. Its numeric indices are stable translation keys. `es.json` and `pt-BR.json` map those keys to complete authored translations. Add new English entries at the end; do not reorder existing entries. Preserve the named `{{color}}`, `{{symbol}}` and `{{name}}` placeholders exactly. `{{name}}` is a canonical character name; colors and symbols are rendered with the same vocabulary as the public admission seals.

`localizeRoomView` accepts only a viewer-filtered `RoomView`. It clones that view and translates explicitly listed narrative fields. It never looks up a dossier, culprit or hidden answer. English engine snapshots, command receipts, identifiers, names and numeric game state remain canonical. The RPC boundary validates and removes `payload.language` before calling the service, then translates the returned view. Changing language therefore does not change command receipt identity.

A narrative can be composed from complete templates (a clue plus its act IV/V extension, a private secret plus a confession, or a location label plus a search title). The translator recognizes only those authored space and title-separator boundaries. An unknown template throws instead of silently presenting English. Localize a canonical view once, at the response boundary.

Run `node --import tsx --test tests/localization*.test.ts` after changing story content or catalogs. The tests check every catalog key, every dossier and confession, all five acts for each of the twenty possible culprits, all twenty assigned slips in each act, every search, every solution and previous-answer explanation. They also check all legal party sizes and shortened games, viewer privacy, stable answer IDs and canonical RPC persistence.

Public validation errors live separately in `errors.ts`. `localizeError` handles the exact known messages and a limited set of authored dynamic templates (phase, gender, available character count and numeric setting bounds). It never translates arbitrary request values or credentials. RPC error codes are classified from the canonical English message before its public text is localized. Unknown exceptions use a generic safe English message; internal database/network failures retain the existing localized temporary-unavailability message. `tests/localization-errors.test.ts` enumerates all static engine/service/RPC errors and validator labels so newly added messages require translations.

Complete literal strings use an exact source-to-index map before the strict template/composition matcher. A local Node 24 benchmark used a legal twenty-player, five-act private view with 100 published clues and 15 automatic evidence items, warmed ten times and translated 100 times per locale. Average translation time (including cloning the view) fell from 2.077 ms to 0.875 ms for Spanish and from 2.010 ms to 0.859 ms for Brazilian Portuguese. These are descriptive local measurements, not timing assertions or deployment guarantees. Interpolated fragments, composition boundaries and missing-entry failures still use the same strict behavior.
